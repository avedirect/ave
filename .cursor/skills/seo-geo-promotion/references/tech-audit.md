# SEO-аудит: технический, ситуационный, CTR и восстановление трафика

Техаудит обеспечивает одно: **нужные страницы в индексе в нужном виде**. Ранжирование дальше решают релевантность, коммерческие факторы, ПФ, ссылки, E-E-A-T. Поэтому каждую находку оценивать по влиянию на продвигаемые URL, а не по числу «ошибок» в сервисе.

## 0. Формат находки и приоритеты

Каждая находка: **проблема → доказательство (URL, скрин, выгрузка) → влияние → решение (ТЗ) → приоритет → ответственный → статус**.

| Приоритет | Что сюда попадает |
|---|---|
| P0 критично | Продвигаемые URL не в индексе / закрыты / 5xx / noindex / неверный canonical; контент не виден боту (JS); сайт падает при обходе; зеркала не склеены |
| P1 высокий | Дубли >10–20% страниц, GET-мусор в обходе, каннибализация посадочных, нет оптимизации посадочных под кластер, тип страницы ≠ типу топ-3, низкий CTR в топ-10 |
| P2 средний | Структура и перелинковка, тонкий контент, расширенные сниппеты, Карты/фиды, внутренние 301, скорость шаблонов в красной зоне |
| P3 низкий | Длина title/description, Title=H1, W3C, ошибки на непродвигаемых URL, alt у декоративных картинок |

**Не ошибки (мифы):** число страниц в индексе само по себе (важен охват интентов); превышение длины Title/Description на 50–100 символов; Title=H1 (сигнал проверить шаблон, не фактор); W3C-валидация; редиректы для двойных слешей, которых нет ни в индексе, ни в ссылках; ошибки на непродвигаемых страницах (если не по всему сайту); «песочница» Яндекса (на деле — нет внешних сигналов). Скрывать счётчики от ботов не нужно.

Шаблоны ТЗ на типовые ошибки (80% повторяются: нет canonical, нет разметки, GET-дубли) ускоряют аудит ~в 10 раз.

## 1. Технический чек-лист по пути документа

### 1.1 Сканирование
- [ ] **Эталонный список продвигаемых URL** (из CMS/семантики) — основа всего аудита. Краулер не увидит страницы без входящих ссылок → для больших сайтов брать выгрузку из CMS.
- [ ] robots.txt: размер/кодировка, «Анализ robots.txt» Яндекса (битые символы, итоговый URL после Clean-param), открыты CSS/JS/картинки; закрыты сортировки, фильтры без спроса, внутренний поиск, корзина, избранное. Не закрывать ИИ-ботов без причины. Шаблон — `schema-and-rendering.md`.
- [ ] Склейка зеркал: http→https и www/без www **для всех URL** (не только главной), слеш, `index.php`/`.html`; одна версия отдаёт 200, остальные — 301.
- [ ] Коды ответа: битые ссылки, **внутренние 301** (заменить ссылки на конечные URL), 5xx — постоянные или под нагрузкой. Хостинг падает ночью, когда обходит робот → «Статистика обхода» и «Мониторинг важных страниц» в Вебмастере.
- [ ] Sitemap.xml: все продвигаемые есть; нет noindex, закрытых, неканонических, редиректов; `lastmod`; несколько файлов по разделам для больших сайтов; добавлен в Вебмастер и GSC. У 30–40% сайтов sitemap кривой.
- [ ] URL: дефис, а не `_`; транслит без лишних цифр; короткие (длина — коммерческий фактор Яндекса); товар — один URL `/product/<slug>` независимо от категории. Не менять URL, если в Яндексе всё хорошо.

### 1.2 Индексация
- [ ] Сверить эталонный список с индексом Яндекса и Google **в обе стороны** («в индексе 120, продвигаем 100» бывает = 80 нужных + 40 лишних). Screaming Frog индексацию не проверяет → Арсенкин, A-Parser, Linkbox; проверять несколькими способами (`site:`, title в кавычках, GSC, Вебмастер) — все ошибаются.
- [ ] % индексации отдельно по Яндексу и Google: >80% норма, 60–80% зона риска, <60% срочный разбор («Просканировано, но не проиндексировано» в GSC ≈ МПК в Яндексе). Google 2024+ индексирует хуже (до 50% неиндекса у обычных сайтов), Яндекс — почти всё.
- [ ] Причины неиндекса: canonical, noindex, X-Robots-Tag, мало входящих внутренних ссылок (1–2 ссылки со страниц, которые сами вне индекса), малополезный/тонкий контент, мусор, размывающий сайт (кейс: «цены на помидоры» на финтех-сайте — удалили, индексация Google выровнялась).
- [ ] Ускорение: IndexNow (Яндекс, Bing), Google Indexing API (200 URL/сутки на аккаунт; кейс: дожали 9% неиндекса → трафик ×3), блок новых материалов на главной, ручная отправка. Код — `schema-and-rendering.md`.
- [ ] Удаление из индекса — `noindex` или 410, **не** Disallow (робот не увидит noindex); 404 висит месяцами.
- [ ] AMP в Яндексе закрыть; AMP-версия noindex-страницы отдаёт 404/403. Корзина/поиск в индексе Яндекса — из-за «обхода по счётчикам Метрики».

### 1.3 Дубли и GET-параметры
- [ ] Поиск: дубли Title в краулере, фрагмент текста в кавычках + `site:`, Вебмастер «Страницы в поиске» (фильтр дублей) и «Статистика обхода» с URL, содержащими `=`, логи, запросы GSC с 2–3 страницами.
- [ ] Реагировать на аномалии (дубли >10–20% страниц), мелочи — по остаточному принципу. Служебные страницы (доставка, оплата) — не дубли.
- [ ] Алгоритм GET-дублей: полезные параметры (пагинация, сортировки со спросом) → ЧПУ + 301 + замена ссылок; **самореферентный canonical везде**; бесполезные — `Clean-param` (Яндекс) + meta noindex без Disallow (Google); nofollow на ссылки сортировок; ежемесячная проверка обхода, новый параметр — сразу в Clean-param.
- [ ] Пагинация: индексируется, canonical на себя, без ссылок на `?page=1`, на стр. 2+ без SEO-текста, «страница N» в title/H1. Комментарии не пагинировать.
- [ ] Варианты товара (цвета) — один URL, варианты текстом (для Google микро-URL проигрывают).
- [ ] PPC-посадочные с подменой 2–3 слов — noindex и вне sitemap. Чужие PDF у себя — закрыть.

### 1.4 Вид в поиске
- [ ] Title/Description/H1 по шаблонам каждого типа страниц (у товаров подставляется «купить в {городе}», цена); нет пустых, однословных, дублирующихся, **с устаревшим годом/акцией**.
- [ ] Ровно один H1; ключ в начале Title, в Description и H1 (разные словоформы), без переспама.
- [ ] Микроразметка: Organization (главная), LocalBusiness (контакты), BreadcrumbList, Product+Offer+AggregateRating, Article+Person; одна основная сущность; только видимое и правдивое. Валидатор + Rich Results Test. Шаблоны — `schema-and-rendering.md`.
- [ ] Расширенные сниппеты: звёзды (aggregateRating), цены (AggregateOffer), таблицы параметров в контенте (Google выводит их в сниппет), быстрые ссылки Яндекса (ссылки на вложенные разделы на самой странице), фиды Яндекса (товары, курсы, врачи, события), основное изображение в Product/Article и в первом экране. Эмодзи в title Google вырезает; в BreadcrumbList/значениях таблиц — работают (опыт практиков).
- [ ] Отзывы о сайте в Яндексе («⋮» у сниппета → «О сайте») — мониторить и отвечать.

### 1.5 Контент и рендеринг
- [ ] Бот видит то же, что человек: текстовая копия/сохранёнка, «Проверить URL» в GSC, «Проверка ответа сервера» в Вебмастере, JavaScript Switcher. Полнота индекса <50% или 10–20 невидимых SEO-элементов на JS-сайте → SSR (ТЗ — `schema-and-rendering.md`; внедрение 4–6 мес., ставить первой задачей).
- [ ] Нет скрытого мусора: меню десктоп+мобайл дважды в коде, «ваш комментарий ожидает одобрения», скрытые формы, текст только в FAQ-разметке (расхождение кода и видимого похоже на клоакинг), латиница вместо кириллицы.
- [ ] Mobile-first: контент, которого нет в мобильной версии, Google не учитывает.
- [ ] Тонкий контент: Word Count и Text Ratio в краулере по основной зоне (исключить header/nav/footer); страницы почти без текста — расширить, склеить 301 или закрыть.
- [ ] Скорость — по **всем шаблонам** (товар, листинг, статья) и по полевым данным CWV в GSC, а не только главная в PageSpeed. Красная зона → сравнить с топом кластера: быть лучше конкурентов достаточно. WebP, lazy load, `srcset`/`<picture>`, меньше тяжёлого JS.

### 1.6 Структура и перелинковка
- [ ] Минимум вложенности (вложенность Яндекса = кратчайший путь кликов от главной; кейс «шторы»: убрали 4–5 уровни → резкий рост), сквозное меню, ссылки с главной на ключевые категории, хлебные крошки, HTML-карта в футере.
- [ ] SEO-фильтры: значения фильтров со спросом — ссылками `<a href>` на отдельные посадочные (для пользователя работают как обычный фильтр).
- [ ] Ссылки на noindex/404 и редиректы «сливают» внутренний вес. Правила перелинковки — `semantics-structure.md`.

### 1.7 Поисковое пространство и внешнее
- [ ] Яндекс Карты/Бизнес, 2ГИС, Google Business (верификация, рейтинг ≥4), Яндекс Товары, Google Merchant Center, YML-фиды, вертикаль картинок.
- [ ] Ссылки: исходящие ведут на живые страницы; входящие открываются; история домена (Web Archive, Ahrefs — тысячи спам-ссылок критичны, единичные нет). Новому/региональному сайту нужны внешние сигналы: статьи с анкорами, каталоги, отраслевые площадки, PR.
- [ ] Вебмастер и GSC: диагностика, ручные санкции, безопасность, регион, «Мониторинг важных страниц», алерты.

### 1.8 Мониторинг (чтобы аудит не устарел)
Алерты Вебмастера/GSC; кастомный алерт в аналитике (органика −50% к прошлой неделе — ловит и снесённый счётчик); цель Метрики на 404 с реферером; отслеживание изменений метатегов (Topvisor); позиции еженедельно (в Яндексе — с реальных устройств, не в инкогнито); плановые краулы со сравнением объёма текста в контейнере; ежемесячная сверка индекса и исключённых; после каждого релиза — проверка рендеринга.

## 2. Ситуационный аудит (от задачи)

Аудит идёт от вопроса бизнеса («поднять категорию», «вернуть позиции», «трафик есть — заявок нет») и **всегда в сравнении с топом**.

1. **Запросы**: общая vs фразовая частота (кейс «ремонт кабины»: ищут душевые кабины), геозависимость, агрегаторы в топе, коммерциализация, сезонность, доля AI-ответов.
2. **Тип страницы = тип топ-3** (коммерция/инфо, листинг/карточка, с топонимом/без). Инфо- и коммерческий интент — разные страницы. B2B-страница без цен с разметкой Article выглядит статьёй и не ранжируется по «купить».
3. **Посадочная против топа**: вхождения, полнота подтем, ассортимент (сильнейший коммерческий фактор Яндекса: у конкурентов 48 товаров на странице — у вас 24), цены, отзывы, доставка/возврат, фото, видео. Отстаёте на пару позиций — превзойти топ на ~20%.
4. **Диагноз по глубине вылета кластера**: из топ-10 на пару дней за топ-100 → техника; в топ-20 → каннибализация/техника; в топ-50 → недооптимизация или переспам (был в топ-10, откатился в 30–40 → убрать лишние вхождения из Title/Description/H1–H5).
5. **Падение после апдейта**: сопоставить дату падения с апдейтами Яндекса/Google, смотреть историю за год (Метрика, Вебвизор), ПФ, индексацию, долю МПК. ~30% обращений — падение после апдейтов (антиспам, качество контента, ПФ). В YMYL падение инфотрафика лечится E-E-A-T (`eeat-trust.md`).
6. **Сниппеты**: спарсить сотни сниппетов своих и конкурентов, сравнить; нет расширенных — точка роста.
7. **Воронка целиком**: соответствие → позиция → CTR → невозврат/конверсия. +20% на каждом этапе дают больше, чем ×2 на одном.

**Факторы (опрос специалистов 2024 + наблюдения 2025):** Яндекс — ПФ фактор №1 (83% опрошенных), но только вместе с текстовой релевантностью; далее полнота темы, отзывы и карточка в Картах; тематические естественные ссылки снова работают. Google — ссылки, текстовая релевантность и глубина темы; ПФ отметили ~20%, эмуляция кликов в Google не работает (NavBoost фильтрует клики по гео/устройству). Накрутка ПФ в Яндексе в 2025 может поднимать позиции в снималках и ронять реальные — не использовать.

## 3. CTR и сниппеты (быстрые победы)

**Быстрый аудит «индексация × CTR» (2–4 часа):**
1. % индексации (см. 1.2).
2. Выгрузка URL с показами/кликами/CTR/позицией (GSC интерфейс отдаёт 1000 строк → API или `scripts/gsc_opportunities.py` по CSV).
3. Статус: 0 показов и кликов → «нет спроса/не ранжируется»; CTR < 0,5 × среднего CTR сайта → «CTR низкий»; иначе «ок».
4. Действие на URL:

| Ситуация | Действие | Приоритет |
|---|---|---|
| Топ-10, показы в норме, CTR ок | Оставить, усиливать ссылками, мониторить раз в 1–3 мес. | — |
| Топ-10, много показов, CTR низкий | Переписать title + description (возможно H1); эффект за 1–2 дня после переобхода | Высокий |
| Топ-30, высокие показы, нет кликов | Анализ выдачи, смена типа контента или рерайт | Средний |
| Долго нет показов, дубль, тема мертва | Склеить 301/canonical с близкой страницей или удалить (404/410) | Средний |

Сегментацию можно отдать LLM (роль «SEO-аналитик», на каждый URL одно действие и обоснование в 1 предложение), но пограничные случаи перепроверять вручную.

**Отбор страниц с аномально низким CTR:** позиция <20, показы ≥100–300 → сортировка по CTR. Эталон — **лучшие страницы своего сайта** (5–15%), а не средние по рынку. Сначала исключить: zero-click (ответ прямо в выдаче), 3–4 рекламных блока сверху, AI-блок, низкую частотность и сезонность. Затем вбить запросы страницы в выдачу и посмотреть свой сниппет глазами.

**Частые дефекты сниппета:** просроченный год/акция в title или description (прогнать выгрузку поиском по «2019…2025»), пустые и однословные мета, глюки шаблонов, неверный топоним, мусор в description, title не совпадает с контентом (растут отказы).

**Формула коммерческого title:** тема в 2–3 словах + регион + коммерческое слово (цена/купить/услуга) + преимущество **из опроса клиентов** (цена «от …», гарантия, срок) + бренд. Пример: «Чистка зубов в Москве от 12 000 ₽ с гарантией — Smile». Не повторять тему в title разных страниц (каннибализация). Title шире, H1 — краткая выжимка («Организационно-правовая форма ООО» / «Что такое ООО»). Инфо- и GEO-формулы — `article-writing.md`.

**Итерации title:** генерировать ≥3 варианта, внедрять и мерить; страница не заходит в топ — менять title до ~10 раз или пересоздать страницу с другим title (наблюдение практика, причина неясна). Яндекс болезненно реагирует на частую смену title — менять обдуманно и фиксировать даты.

## 4. Восстановление трафика и точки роста

- **«Утерянные ключи»**: GSC → страница → «Запросы», позиция <20 → запросы и синонимы, которых **нет на странице явно** → дописать 1–3 абзаца под них (не просто вписать слово) + 20–30 контекстных ссылок со старых тематических страниц с анкорами из этих ключей (ссылки в первой трети текста). Автоматически — `gsc_opportunities.py --check-content`.
- **Striking distance**: запросы на 4–20 позициях с большими показами — дожимать вхождениями в title/H1, новым блоком, перелинковкой.
- **Реанимация по GSC**: страницы с максимальной потерей кликов год к году → их запросы + заголовки топа + задачи пользователя → дописать недостающие разделы.
- **Каннибализация**: по запросу ранжируются 2+ страницы → выбрать главную, развести интенты или склеить 301, перелинковать на главную единым анкором.
- **Статья не набрала трафик за 6 месяцев**: сравнить с 3–4 слабыми конкурентами из топа в текстовом анализаторе, добавить недостающие слова и подтемы, сократить абзацы, оглавление, видео, картинки, отправить на переобход. Обновляя — удалять устаревшее; восстановление до полугода.
- **Тонкий контент и дубли**: расширить, склеить или удалить — экономит краулинговый бюджет и снимает каннибализацию; удаление дублей товаров (3–5 копий) даёт рост.
- **Трафик есть, заявок нет** — чинить сайт, а не SEO: сегменты клиентов, опрос ~10 клиентов («5 важнейших факторов выбора, оценка 1–5»), страницы под сегменты, доказательства (таблицы цен, галереи работ), лид-формы по триггерам, чат, Telegram-кнопка. Норма конверсии ~3%, хороший сайт 5–10%. Нет ни трафика, ни заявок — сначала проверить спрос.
- **SEO отчитывается деньгами**: доход с текущих страниц, доход с новых, видимость новых страниц (>60%), план-факт по месяцам; внешние спады доказывать трафиком, видимостью и реальными позициями.

## 5. Инструменты и их ограничения

- **Screaming Frog** — анализ, а не судья: пресет «Googlebot Smartphone»; игнорировать Pagination (rel next/prev мёртв), Blocked Resource, Indexability по robots; «Same as H1» — не ошибка. Силён: коды ответа, Compare-краулы, расписание, XPath-извлечение, hreflang, soft 404, страницы без счётчиков, поиск мест для перелинковки, подключение API GSC/GA. Для Яндекса учитывать Clean-param и Вебмастер.
