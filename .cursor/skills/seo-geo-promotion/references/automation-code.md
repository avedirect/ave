# Автоматизация SEO: Python, API, ИИ-агенты

## Принципы

1. Автоматизировать **регулярные** задачи, уже давшие эффект вручную на ~10 страницах. Сначала SEO-логика (источники, фильтры, веса, формат выхода), потом код.
2. Данные — **по API**, а не из веб-интерфейсов: интерфейсы режут объём и агрегируют.
3. Пайплайн, который сам собирает данные и отправляет ТЗ/отчёт, надёжнее регламентов.
4. Проверять вывод вручную: пропуски данных сдвигают столбцы, тег контента может появляться только после JS, XML-провайдеры отдают не все запросы.
5. Перед написанием своего — поискать на GitHub / в готовых библиотеках.

## Источники данных

| Источник | Что даёт | Нюансы |
|---|---|---|
| Google Search Console API | запросы × страницы × даты: клики, показы, CTR, позиция | до 25 000 строк за запрос с пагинацией, по дням, глубина ~16 мес. |
| Яндекс.Вебмастер API | запросы с показами, индекс, обход, ошибки | OAuth-токен Яндекса |
| Wordstat API | частоты | тот же OAuth; до 2000 результатов за запрос |
| Метрика API | поисковые фразы, страницы входа, цели | сэмплирование обходится циклом по дням; фразы до 1 визита — только `date` + `lastSearchPhrase` |
| XMLRiver / XMLStock / DataForSEO | выдача Яндекса/Google, Wordstat | таймауты брать из документации (60 с, а не «30 по мнению модели») |
| Keys.so, SpyWords, Ahrefs, Semrush | семантика конкурентов, видимость, ссылки | Keys.so может отдать файл в cp1251; Ahrefs MCP — лимиты API малы |
| A-Parser | массовый парсинг Wordstat/выдачи | сотни запросов в минуту |
| IndexNow / Google Indexing API | отправка на индексацию | Indexing API — права владельца GSC, 200 URL/сутки |

Ключи — в переменных окружения, не в коде.

## Рабочая среда

- Анализ: VS Code + Jupyter + pandas (`read_clipboard()`, `merge` вместо ВПР, `groupby` — закрывают ~90% задач), `read_xml` для sitemap.
- Интерфейс для команды: Telegram-бот, Streamlit/Gradio, Tkinter→.exe; расписание — cron на VPS.
- n8n/Make — для простых цепочек; любые отклонения проще в коде.
- Лемматизация русского: `pymystem3` (MyStem) или `pymorphy3`.
- Краулинг: `advertools` (коды ≠200, пустые title/description/H1, дубли, микроразметка), Screaming Frog (Custom Extraction XPath, Compare двух краулов, расписание; пресет «Googlebot Smartphone»).

## Типовые автоматизации (готовые рецепты)

1. **Низко висящие фрукты** — запросы с показами (позиции 4–20), точного вхождения которых нет в Title/H1/тексте страницы → список «добавить вхождения» контент-отделу. Готовый скрипт: `scripts/gsc_opportunities.py`.
2. **Каннибализация** — `groupby(['query','page'])`: по одному запросу несколько страниц делят клики/показы → выбрать целевую, развести релевантность.
3. **Реанимация трафика** — GSC: месяц vs тот же месяц год назад, сортировка по разнице кликов → по каждой странице: её запросы из GSC + заголовки топа (XMLRiver) + боли ЦА (JTBD) → LLM строит «идеальную структуру» → дописывает только недостающие разделы → редактор.
4. **CTR-тайтлы** — запросы + CTR + клики из GSC → новый Title (цифры, скобки, выгода, интент) → итерации с примерами удачных (1-я итерация ~50% улучшений, 3-я ~90%; минимум 3). Google переписывает ~30% тайтлов — такие менять. Яндекс болезненно реагирует на смену тайтлов → менять порционно, наблюдать.
5. **ТЗ на статью** — кластер → выдача → URL-чемпионы (чаще всего в топах кластера) → title + H1–H3 у 5–10 → LLM-промпт структуры (см. `article-writing.md`) → Google Sheets/почта.
6. **Индексация** — sitemap → проверка индекса → в IndexNow/Indexing API только неиндексированные.
7. **Clean-param** — выгрузка URL с GET-параметрами из Вебмастера → уникальные параметры по путям → готовая директива.
8. **Ссылка с главной** — проверить, что каждая продвигаемая страница доступна в 1 клик с главной.
9. **Текстовый анализ против топа** по зонам (текст, title, ссылки, alt): перекосы (у нас слово 100 раз, у топа 2–5) и недостающие слова (встречаются у ≥N страниц топа). Задавать контейнер основного контента — проверять, есть ли он в исходном HTML.
10. **Приоритизация каталога** — семантика конкурентов → n-граммы 2–5 слов → число запросов и сумма частот на n-грамму.
11. **Массовые описания карточек** — CSV (URL, H1, характеристики) → LLM API (system prompt один раз, пример удачного описания, ≤600 знаков, 2 абзаца) → CSV (URL; описание) → заливка скриптом. URL с категорией и артикулом информативнее H1, передавать оба. Очистка: лемматизировать выход, найти странные леммы/латиницу, перегенерировать ~2% брака. 1000 знаков кириллицы ≈ 500 токенов; учитывать лимиты токенов в минуту/день.
12. **Скор доноров/запросов** — несколько метрик с весами (сумма 100) и потолками насыщения → средневзвешенный балл; Яндекс-показы ×0,7.
13. **Мониторинг**: алерт «органика −50% к прошлой неделе», цель на 404 с реферером, отслеживание изменений метатегов, плановые краулы со сравнением объёма текста в контейнере.

Пример GSC API (каркас):
```python
from google.oauth2 import service_account
from googleapiclient.discovery import build

creds = service_account.Credentials.from_service_account_file(
    "gsc.json", scopes=["https://www.googleapis.com/auth/webmasters.readonly"])
gsc = build("searchconsole", "v1", credentials=creds)

def fetch(site, start, end, dims=("query", "page")):
    rows, start_row = [], 0
    while True:
        r = gsc.searchanalytics().query(siteUrl=site, body={
            "startDate": start, "endDate": end, "dimensions": list(dims),
            "rowLimit": 25000, "startRow": start_row}).execute()
        batch = r.get("rows", [])
        rows += [dict(zip(dims, x["keys"]), clicks=x["clicks"], impressions=x["impressions"],
                      ctr=x["ctr"], position=x["position"]) for x in batch]
        if len(batch) < 25000:
            return rows
        start_row += 25000
```

## RAG-перелинковка статей по смыслу

Статьи → резюме в 3 абзаца (хвосты «как добраться/что взять» путают эмбеддинги) → эмбеддинг резюме **одной моделью на всю базу** (разные модели = разные пространства) → векторный поиск топ-5 по косинусу (близкие ≈0,15–0,25 расстояния; ~0,8 — ошибка) → LLM-редактор вставляет 1–3 ссылки органично, только при уместном месте → обратно в CMS. Стоимость: 550 статей ≈ 1,2 $ (DeepSeek API) + локальные эмбеддинги.

Промпт: «Ты опытный редактор и SEO-специалист. Вот статья <article>…</article> и связанные статьи <related>…</related>. Вставь 1–3 ссылки на связанные статьи органично в существующие предложения, только там, где это уместно для читателя. Не меняй смысл и стиль. Верни полный текст».

## Парсинг

Порядок выбора: (скрытое) API во вкладке Network → статика `requests` + `BeautifulSoup` → динамика Playwright (часто и много) / Selenium (редко). Защита по нарастающей: реалистичные headers + задержки + ротация UA → прокси → `undetected-chromedriver`/`patchright` → эмуляция отпечатков → сервис капчи. Headless палится по `HeadlessChrome` в UA. curlconverter: DevTools → Copy as cURL → готовый код requests. URL брать из sitemap, а не краулить. LLM-парсеры (ScrapeGraphAI, Crawl4AI — отдаёт Markdown для LLM) переживают смену вёрстки, но стоят токенов. Асинхронные краулеры ограничивать по скорости — можно «положить» сайт.

## ИИ-агенты и вайб-кодинг

- Детальное ТЗ с примером «вход → выход»; одна фича за итерацию; бэкап каждой версии; «скопируй файл N в N+1 и правь копию»; «не вноси изменений вне ТЗ».
- Документацию API вставлять текстом; лимиты, таймауты и параметры сверять самому.
- Сразу закладывать прогресс-бар, папку логов, кнопку «стоп»; дебаг ≈70% времени.
- «Перед выполнением задай вопросы и запроси недостающие данные». «Найди узкие места в этом плане».
- Модели по сложности: сильная — проектирование/план, средняя — рутина, дешёвая — роутинг/классификация/тайтлы (экономия лимитов ×5–10).
- Чат-API не хранит историю — её пересылают каждый раз; следить за ростом контекста и расходами.
- Агентам не давать платёжные и персональные данные; ПД обезличивать перед RAG.
- Генерация сайта: дизайн по скриншотам конкурентов из нужного поисковика (давать самому — агенты ищут в Google/Bing и упираются в капчи), сборка — агент в режиме плана; требовать чистый HTML/CSS/JS без CDN, адаптив, header/footer отдельными шаблонами, Schema.org, сохранение старых URL (CSV «URL;H1»); сохранять версии (1.html, 2.html) и сравнивать — модель при правках удаляет блоки; тест на поддомене.
