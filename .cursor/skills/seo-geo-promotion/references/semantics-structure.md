# Семантика, структура сайта и перелинковка

## Принцип: семантика = спрос

Воронка: спрос → ключи → URL страницы → обход роботом → индекс → релевантность → позиции → трафик → лиды → продажи. **Нет страницы под спрос — нет трафика.** Рост крупного сайта идёт через новые посадки под кластеры (теги, подборки, срезы фильтров, статьи), а не через ключи в текстах. Без расширения структуры трафик постепенно сползает (до ×4 за год; у инфосайтов падение тянется до 2 лет). Чтобы получить SEO-трафик, в ~90% случаев нужны новые посадки, минимум — переписанные заголовки и тексты.

**Язык покупателя, а не продавца.** Кейс ТРЦ: вместо «аренда зала 100 м²» (≈87 запросов/мес) — посадки «банкетный зал на 100 человек» (≈3000/мес) → контекстный трафик ×5–7 при бюджете +20%, органика ×2.

## Сбор ядра

Источники (чем больше, тем полнее; крупные заказчики требуют ~10): Wordstat (Яндекс даёт точную частоту, Google — интервалы), поисковые подсказки по API (часто расширяют ядро ×2–3), Яндекс.Вебмастер и GSC (реальные запросы), Keys.so / SpyWords / Mutagen, Букварикс (локальная база), Ahrefs/Semrush (для Google и буржа), XMLRiver/XMLStock (Wordstat и выдача без банов), базы Пастухова/MOAB, Key Collector. Пример: расширение с 12 тыс. до 76 тыс. ключей (×6 охвата).

Чистка:
- стоп-слова осторожно — «фото», «бесплатно», «отзывы» в части ниш целевые;
- сравнивать общую и фразовую частоту («ремонт кабины» — общая высокая, фразовая низкая: ищут душевые кабины);
- отсекать хвост по Парето: в коммерции частота <4–5, в инфо кластер <100 мал;
- Яндекс-частоты можно умножать на ~0,7 (накрутки ПФ), коммерческим маркерам давать надбавку — единый скор из разных источников.

**Кластеризация по выдаче** (топ-10, порог общих URL 3–5): исключать маркетплейсы и агрегаторы при анализе конкурентности; отмечать кластеры, где в топе главные страницы (конкурировать внутренней страницей тяжело). Яндекс детальнее разделяет интенты, под Google кластеры обобщённее. Битые серпы = кривая кластеризация.

**Формат ядра — 2 листа**: (1) кластеры с фразами; (2) «индекс»: категория → подкатегория → кластер (главный запрос, суммарная частота, ID, число фраз, позиции сайта). Сортировка по частоте + скоринг, руками разбирать верх списка.

**Слой сущностей (для GEO и ТЗ):** таксономия (смартфон → iPhone → 15), онтология (модель → цвет/материал/размер), триплеты «сущность–связь–сущность». 3–10 сущностей на интент. Независимая проверка «ДНК темы»: смысл не должен теряться (пример: «мытьё окон снаружи» схлопнулось в «мытьё окон»).

**ChatGPT в семантике — точечно:** тайтлы, синонимы, расширение 50–100 ключей вокруг маркера (затем прогон через сервисы частот), словарь узкой ниши. Большие массивы и частотность — не через чат; массивы на миллионы строк — пусть модель пишет код на pandas.

## Анализ ниши и конкурентов

1. Базовый запрос → сервис (Semrush Keyword Magic, Keys.so) → компактная релевантная выгрузка; уточнять, пока выдача не попадёт в бизнес-вектор.
2. Конкуренты по этой семантике из сервиса; отсеять другую бизнес-модель (Википедия, YouTube, агрегаторы).
3. Таблица ~30 параметров на конкурента ≤5 минут (пакетные выгрузки): трафик и каналы (SimilarWeb), возраст домена, ссылочный профиль, страниц в индексе, запросов в топ-10, доля брендового трафика (30–50%+ = нишу сложно взять), PageSpeed главной (моб.).
4. Трафик из сервисов — только сравнительный, усреднять 3–5 источников (ошибка до ×10).
5. Пересечение семантики топ-3 сайтов ниши (диаграмма Венна) — быстрое ядро в незнакомой нише.

## Метод «SEO-дизайн» (функциональный анализ топа)

Когда: редизайн/переезд уронил трафик, новый проект, конкуренты с тем же ассортиментом выше.
1. Полное ядро → классифицировать кластеры по типам страниц (главная, листинг, подборка/тег, карточка, статья, калькулятор…).
2. Для каждого типа — топ по группе запросов, полностраничные скриншоты (доказательства).
3. Разобрать элементы в Excel: шапка (телефон, поиск, корзина), меню, крошки, коммерческий блок (сроки, доставка, гарантия), фильтры, отзывы, кейсы, клиенты, акции, FAQ, подвал…
4. Скоринг: доля конкурентов с элементом. **≥30% — внедрять.** Итог — ТЗ «элемент — важность — что сделать».

Тип страницы = тип топ-3 (коммерция/инфо, листинг/карточка, главная/внутренняя). По «заказать розы» карточкой одного букета не продвинуться.

**Ядро как аудит:** кластеры без позиций выявляют шаблонные одинаковые метатеги, поддомены-дубли, фильтры на «#» (поиск видит только корень), пагинацию/404 в выдаче, мусорные GET-параметры, персональные данные в URL, дыры в функционале фильтров (собирают ~30% спроса при наличии ассортимента).

**Массовые шаблоны (UGC, каталоги):** n-граммы по семантике среза → частотные паттерны (город, тип, бренд) в шаблоны Title/Description из полей карточки. Приоритизация огромного каталога: склеить семантику конкурентов → n-граммы 2–5 слов → сумма частот по n-грамме («Ford Focus»: 5 625 запросов, суммарная частота 14 404) → с чего начинать.

**Микрокластеры:** Яндекс лоялен к узким страницам, Google — нет: варианты товара (цвета) объединять на одной странице, для Google — общая категория с блоками подкатегорий. Крупный проект — внедрять ядро целиком, ВЧ подтянутся после внедрения всей семантики; при малом бюджете — по возрастанию конкуренции (≈30 страниц в месяц).

## Структура

- Минимум вложенности (кейс «шторы»: товары с 4–5 уровня подняли выше → резкий рост), подробное сквозное меню, ссылки с главной на ключевые категории (проверять «ссылку с морды» для каждой продвигаемой страницы).
- Хлебные крошки (+ `BreadcrumbList`), HTML-карта сайта в футере.
- URL: только ключевые слова, без предлогов и эмодзи, ~до 60 символов; один URL товара независимо от категории (`/product/<id-slug>/`).
- Блог — в папке основного домена (перенос с поддомена в папку с 301 давал ×1,5–3 трафика блога).
- Мультиязычность — папки + hreflang; семантика под каждый язык собирается отдельно, не переводится.
- Плоская структура норм для инфопроектов (1000 страниц в 10–15 разделах), для коммерции — иерархия.

## Перелинковка

- **Обратная перелинковка** (крошки, ссылка с товара на категорию, с дочки на родителя) аккумулирует вес на категориях, которые продвигаются по ВЧ.
- ≥5 входящих внутренних ссылок на важную страницу, ≥3 на второстепенную; 0–1 → «сирота».
- Ссылки в основном контенте и выше по странице весомее сайдбара/футера (утечка документации Google).
- Анкоры: короткие (1–2 слова); единый точный анкор на страницу работал лучше вариативных (исследование на 50 сайтах); «купить» в анкорах не злоупотреблять (Яндекс учитывает переспам анкоров).
- Источники ссылок: меню, футер, плитка подкатегорий, крошки, HTML-карта, блог → коммерция (≈2 коммерческих анкора на статью), «похожие/популярные», ссылки со служебных страниц (у них много сквозного веса).
- Семантический кокон: родитель описывает каждую дочку абзацем со ссылкой; дочка в первом абзаце ссылается на родителя и своих детей.
- Сквозной блок 10–20 ссылок (например, на города области) в футере давал резкий рост этих страниц в Яндексе.
- Массовая «хитрая» автоперелинковка по ключам заметного роста не даёт; база — крошки, категории, 2–5 тематических ссылок из текста. Смысловая (RAG) перелинковка статей — см. `automation-code.md`.
- Каннибализация: обе страницы в топе — не трогать; иначе развести текстовую релевантность (Title/H1 без чужих запросов) и поставить анкорные ссылки на целевую.
- Внешние ссылки на авторитетные источники не прятать (nofollow/скрипты не нужны).
- Эффект: Яндекс — от пары дней на трастовом сайте, Google — ~неделя, молодой сайт — 1–2 месяца.

## SEO + Директ

Запускать Директ на SEO-структуру (те же посадки и кластеры): выше ROI, широкое ядро снижает цену лида; по наблюдениям, контекст подтягивает органику (+~50% в кейсе, после отключения сползает за ~месяц). Работающие SEO-заголовки — в объявления. Компромисс: 1–2 месяца быстрый Директ, параллельно готовится SEO-структура.
