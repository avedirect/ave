# SEO + GEO продвижение: статьи, аудит, код

База знаний собрана из ~50 вебинаров практиков (SEO-конференции, исследования на 10 млн запросов, кейсы агентств и inhouse) за 2021–2025 гг. Подробности и цифры — в `references/`, готовые инструменты — в `scripts/`.

## Базовые принципы (применять во всех режимах)

1. **SEO — фундамент GEO.** Нейроответы собираются из поискового индекса, но топ-10 не гарантирует попадания (в AI Overviews лишь ~30% источников из топ-10). Нужны оба слоя: релевантность для поиска + блоки-ответы для LLM.
2. **Спрос и интент первичны.** Не писать и не создавать страницу без проверки спроса и типа выдачи: тип страницы = тип топ-3 (коммерция/инфо, листинг/карточка).
3. **Полнота > уникальность.** Раскрыть интент полнее топа на 20–30%: подтемы, цифры, таблицы, сравнения, FAQ. Уникальность ради уникальности не работает.
4. **Прямой ответ первым.** Первое предложение статьи и каждого H2 — ответ на вопрос заголовка; затем детали.
5. **Доверие видно сразу.** Автор-эксперт, даты, источники, отзывы, реквизиты. YMYL — максимальные требования.
6. **Бот должен видеть контент.** Текст, ссылки, разметка — в исходном HTML (SSR/SSG). LLM-боты JS не исполняют.
7. **Влияние, а не количество ошибок.** В аудите приоритет — продвигаемые URL и аномалии; мелочи (Title=H1, W3C, длина мета) — в конец.
8. **Яндекс ≠ Google.** Яндекс: ПФ + текстовая релевантность, коммерческие факторы, Карты и отзывы, Clean-param, Microdata понимает лучше. Google: контент + ссылки, mobile-first, хуже индексирует, JSON-LD. Рекомендации давать с пометкой, для какого поисковика.
9. **Честность данных.** Помечать, где факт подтверждён исследованием, а где мнение практика. Не обещать позиции и трафик. Не предлагать накрутки ПФ, скрытые промпты, фейковых авторов и рейтинги — это анти-паттерны с риском санкций.
10. **Изменения — как эксперимент.** Группа тестовых и контрольных страниц, замер через 2 недели и 2 месяца.

## Выбор режима

Определи, что нужно пользователю, и прочитай соответствующие справочники **перед** работой:

| Запрос пользователя | Режим | Читать |
|---|---|---|
| Написать/переписать статью, ТЗ копирайтеру, контент-план, текст под нейроответы | **A. Статья** | `article-writing.md`, `geo-ai-answers.md` §3; для YMYL — `eeat-trust.md` |
| Аудит сайта/страницы, индексация, падение трафика, CTR, «почему не в топе» | **B. Аудит** | `tech-audit.md`; GEO-аудит — `geo-ai-answers.md`; доверие — `eeat-trust.md` |
| Микроразметка, head, robots, sitemap, SSR, IndexNow, скрипт/автоматизация | **C. Код** | `schema-and-rendering.md`, `automation-code.md` |
| Семантика, кластеризация, структура сайта, перелинковка, стратегия | **D. Стратегия** | `semantics-structure.md`, `geo-ai-answers.md` §2, §6 |

Если запрос смешанный (например, «проведи аудит и перепиши страницу») — выполняй режимы по очереди: аудит → план → контент → код.

Если не хватает данных (URL, ниша, регион, целевые запросы, выгрузки GSC/Вебмастера, CMS) — **сначала задай вопросы**, кратко и списком. Не выдумывай частотности, позиции и метрики сайта: либо получи их (скрипт, выгрузка, пользователь), либо явно пометь как допущение.

## Режим A. Статья (SEO + GEO)

1. **Тема и интент.** Проверить спрос (Wordstat/GSC), тип выдачи и наличие AI-блока; при ≥5 общих URL в топе запросы объединяются в одну статью. Для коммерческой ниши со смешанным интентом нужны и листинг, и статья-рейтинг.
2. **Анализ топа.** Подтемы и элементы, которые есть у ≥30% конкурентов (таблицы, FAQ, калькуляторы, мнение эксперта, видео), — обязательны; плюс 20–30% подтем из query fan-out.
3. **ТЗ / структура** по шаблону из `article-writing.md` §2–3: title и H1, прямой ответ 40–60 слов, H2 = подзапросы/промпты, таблица, список, FAQ, CTA, автор, даты, перелинковка.
4. **Текст.** Каждый H2 начинается с ответа; блоки 120–180 слов; цифры с источниками; без воды и переспама; термины поясняются; в YMYL — проверяющий эксперт и дисклеймер.
5. **Код страницы** (если нужен): BlogPosting/Article + Person + BreadcrumbList (+ FAQPage, если FAQ видим), head — из `schema-and-rendering.md`.
6. **Проверка** по чек-листу `article-writing.md` §5 и `geo-ai-answers.md` §9; при наличии URL — `scripts/seo_page_audit.py`.

**Формат выдачи статьи:**

```markdown
**Title:** … (до ~70 симв.)   **Description:** … (до ~160 симв.)
**URL:** /…/   **H1:** …
**Целевые запросы:** основной; дополнительные; промпты для нейросетей
**Автор / проверил:** …   **Дата публикации / обновления:** …

[Прямой ответ 40–60 слов]
[Оглавление]
## H2-вопрос → ответ первым предложением → детали, таблица/список
…
## Частые вопросы
## Вывод + CTA
**Перелинковка:** откуда ставить ссылки сюда и куда ссылаться отсюда (анкор → URL)
**Микроразметка:** JSON-LD блок
```

Для ТЗ копирайтеру — тот же каркас, но вместо текста: что раскрыть в каждом H2, обязательные факты/таблицы, объём, ключи и слова-подсветки, примеры конкурентов, запреты.

## Режим B. Аудит

1. **Уточнить цель**: техаудит всего сайта, аудит страницы/кластера, падение трафика, GEO-видимость, «трафик есть — заявок нет».
2. **Собрать данные**: эталонный список продвигаемых URL, выгрузки GSC/Вебмастера (страницы, запросы, индексация), краул, robots/sitemap. Запустить скрипты:
   - `python scripts/seo_page_audit.py URL [URL ...] [--file urls.txt] [--ua google|yandex|browser] [--json]` — on-page SEO + GEO по каждому URL (коды, robots и ИИ-боты, мета, canonical, заголовки, CSR, разметка, GEO-сигналы, оценка из 100).
   - `python scripts/gsc_opportunities.py export.csv [--min-impr 30] [--pos-from 4] [--pos-to 20] [--top 40] [--check-content N]` — запросы на 4–20 позициях с потенциалом кликов, низкий CTR против кривой, каннибализация, проверка вхождений запроса в title/H1/текст.
   - Зависимости: `pip install requests beautifulsoup4`.
3. **Пройти чек-лист** `tech-audit.md` §1 по пути документа: сканирование → индексация → дубли → вид в поиске → контент/рендеринг → структура → поисковое пространство → мониторинг. Для ситуационной задачи — §2, для CTR и роста — §3–4, для GEO — `geo-ai-answers.md` §4–7, для доверия — `eeat-trust.md`.
4. **Сравнить с топом** по тем же пунктам — без сравнения выводы не делать.
5. **Отчёт** с приоритетами.

**Формат отчёта аудита:**

```markdown
# Аудит {сайт/страница} — {дата}
## Резюме
3–5 главных проблем и ожидаемый эффект от их решения (без обещаний цифр).

## Критично (P0) / Высокий (P1) / Средний (P2) / Низкий (P3)
| # | Проблема | Доказательство (URL, данные) | Влияние | Решение (ТЗ) | Поисковик | Кто |
|---|---|---|---|---|---|---|

## Точки роста
Запросы/страницы с потенциалом (из GSC), недостающие страницы и блоки.

## GEO-видимость (если в задаче)
Доля AI-ответов в ядре, упоминания бренда, URL в источниках, что мешает.

## План внедрения
Неделя 1–2 → месяц 1 → месяцы 2–3; что и когда замерять.
```

Не вываливать сотни мелочей: группировать однотипные ошибки (одна строка + список URL в приложении).

## Режим C. Код для SEO/GEO

- **Микроразметка**: только то, что видно на странице и правда; самый конкретный тип; главная сущность (`mainEntity`), Person/Brand с `sameAs`; Product с `offers`, `hasMerchantReturnPolicy`, `shippingDetails`. Шаблоны JSON-LD — `schema-and-rendering.md` §2. Для Яндекса допускается Microdata; GTM-разметку Яндекс не видит.
- **Head**: title, description, canonical (самореферентный), robots, OG, hreflang, viewport — §3.
- **robots.txt / индекс**: Clean-param для Яндекса, noindex без Disallow для Google, 410 для удаления, ИИ-боты открыты — §4. **IndexNow / Indexing API** — §6.
- **JS-сайты**: SSR/SSG/ISR, ТЗ на SSR по типам страниц, пример Next.js App Router (`generateMetadata` + JSON-LD) — §5.
- **Скрипты и автоматизация** (GSC API с пагинацией 25 000 строк, Вебмастер, Метрика, парсинг, RAG-перелинковка, кластеризация) — `automation-code.md`. Правила: логи и прогресс, остановка по Ctrl+C, лимиты API, кэширование, выход в CSV/Markdown; секреты — в переменных окружения.
- Любой код после написания проверить: валидатор schema.org / Rich Results Test, «Анализ robots.txt» Яндекса, запуск скрипта на реальном URL или тестовом CSV.

## Режим D. Семантика и стратегия

1. Семантика = спрос: несколько источников (Wordstat, подсказки, GSC/Вебмастер, конкуренты через Keys.so/Spywords), чистка, кластеризация **по выдаче** (затем проверка смыслом).
2. Ядро в формате: кластеры → страницы (есть/нужно создать) → тип страницы → приоритет (спрос × коммерциализация × реалистичность).
3. Структура: минимум вложенности, сквозное меню, SEO-фильтры ссылками, хабы; перелинковка (каждая важная страница — ≥3–5 входящих ссылок с единым смыслом анкора).
4. GEO-слой: доля AI-ответов в ядре, промпты (инфо, сравнительные, разговорные), площадки-источники ниши, план офсайт-упоминаний.
5. План: что создать/доработать по месяцам, KPI — доход и заявки с текущих и новых страниц, видимость, упоминания в нейроответах.
Детали — `semantics-structure.md`, `geo-ai-answers.md` §2, §6.

## Скрипты

- `scripts/seo_page_audit.py` — аудит одного или многих URL (Markdown-отчёт или JSON).
- `scripts/gsc_opportunities.py` — точки роста по CSV-выгрузке GSC или Вебмастера (русские и английские заголовки, кодировки utf-8/cp1251).
