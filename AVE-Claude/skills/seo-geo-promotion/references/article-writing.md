# Написание SEO + GEO статей: от темы до обновления

Номера в скобках — источники-вебинары (для сверки при сомнениях).

## 1. Выбор темы

**Проверка интента (обязательно до написания).** Вбить запрос, прокликать 4–5 результатов топа:
- в топе магазины/листинги → статью НЕ писать, это коммерческий запрос (пример: «плинтус» — коммерция, «какой плинтус выбрать» — инфо);
- в топе статьи → пишем; тип материала (гайд, рейтинг, сравнение, how-to) = тип топ-3.

**Источники тем:**
1. Бизнес: целевые товары/услуги + сезонность (публиковать ДО сезона).
2. Wordstat с регулярным выражением: маркер + вопросительные слова (как, чем, почему, можно ли, зачем, какой, сколько, рейтинг, лучший, отзывы, советы).
3. Блоги конкурентов: домен → Keys.so «страницы» → фильтр по папке `/blog/` → темы с наибольшим числом ключей. Сильный домен — широкие темы; молодой — узкие («спальня и детская в одной комнате», а не «дизайн детской»).
4. Модификаторы: выгрузить ~5000 фраз по маркеру → «уникальные слова» (Букварикс) → по каждому однословнику (лучший, влажный, с лидаром…) смотреть фразы и интент. 40–50 тем за день на одну товарную группу.
5. Темы воронки: документы/разрешения; неисправности («шумит», «не включается»); уход и эксплуатация; сравнения «X vs Y»; рейтинги и «список компаний»; тюнинг/доработки.
6. Новые хвосты для существующих статей: Яндекс.Вебмастер и GSC → запросы с показами, которых нет в тексте.

**Склейка/разделение.** Две фразы = одна статья, если в их топ-10 совпадает ≥5 URL. Иначе — разные статьи (иначе каннибализация).

**Кластерная стратегия, а не одиночные статьи:** якорный гайд (ссылается на все) + how-to + «как выбрать» + рейтинги + сравнения — всё перелинковано. Одиночная статья не по профилю сайта «умирает». Темп: ≥1 статьи в неделю или 2–4 в месяц; первые 2–3 месяца смотреть, что «залетает», и расширять эти кластеры.

## 2. ТЗ на статью (шаблон)

```
Тема / интент / тип материала (гайд | рейтинг | сравнение | how-to | что такое)
Целевые запросы: [3–10 фраз] + уникальные слова из них
Конкуренты (релевантный топ-10 без «чужих» трастовых сайтов): URL + объём → средний объём
Title / Description / H1 (черновики)
Структура H2–H3 «лучше рынка»: объединение заголовков ВСЕХ конкурентов, без дублей, свой порядок
  + 20–30% подтем из query fan-out (остальное — в отдельные статьи)
LSI/тематические слова: только встречающиеся у ≥3 конкурентов (однословники обязательны)
Сущности (entities): бренды, модели, термины, параметры — в логическом порядке
Обязательные блоки: прямой ответ сверху, таблица, список, FAQ, вывод, CTA
Медиа: N фото/схем, видео, инфографика
Ссылки: на какие категории/статьи (анкоры), внешние авторитетные источники
Автор / эксперт-проверяющий
```

Главное в ТЗ — структура + список слов/сущностей. 2–3 вхождения ключа достаточно; «25 вхождений по совету сервиса» — переспам. Лучше добавить потом, чем вычищать.

**Промпт query fan-out** (0050):
> Сделай query fan-out для ключа «[X]» в стране [Y] на языке [Z]. Определи интент, не смешивай навигационный, информационный и коммерческий. Выведи популярные варианты подзапросов, остальные классифицируй по свойствам.

**Промпт структуры из топа** (0098):
> Нужна структура статьи, которая привлечёт трафик из поиска. Вот иерархии H1–H3 статей из топа: [вставить]. Пойми интент и целевую аудиторию, что для неё ценно, и сделай максимально полезную структуру, которая выйдет в топ. Не копируй структуру одного конкурента. Плоская иерархия: много H2, H3 только где нужно, без H4.

## 3. Структура и шаблон страницы статьи

Первый экран: хлебные крошки → H1 → подводка → автор/дата. Без огромной фоновой картинки на весь экран.

1. **H1** — один, с ключом, без спама.
2. **Прямой ответ в первом предложении** (40–60 слов): точное или разбавленное вхождение запроса + конкретика. Затем «подробнее ниже». Это ответ на вопрос статьи, а не саммари всего текста. Даёт featured snippet, быстрый ответ Яндекса, AI Overviews, источники Алисы.
3. **Подводка 300–500 знаков** с конкретным обещанием: «Эксперты проанализировали 30 брендов и составили рейтинг по цене и качеству». Плохо: «Не знаете, как выбрать? Читайте нашу статью».
4. **Кликабельное оглавление** (якоря).
5. **Тело — плоская структура**: много H2 с ключами и фрагментами запросов, мало H3, без H4. Вопрос в заголовке → ответ сразу первым предложением под ним. Креативные заголовки без ключей — только для очень сильных доменов. Ключи в нижних блоках весят меньше всего.
6. **Блоки, которые цитируют LLM и быстрые ответы**: списки, нумерованные шаги, таблицы сравнения/параметров, плюсы и минусы, цифры с источниками, определения «X — это…».
7. **Для рейтингов** — на каждый пункт: фото, оценка, описание ~500 знаков с вхождениями, плюсы/минусы, характеристики, ссылка на товар.
8. **FAQ** внизу (вопросы из подсказок, PAA, GSC, конкурентов), коротко и по делу.
9. **Вывод** с ключом + **CTA** (форма, купон, калькулятор, мини-квиз, карточки товаров). Из-за zero-click CTA важнее: несколько в статье и после.
10. **Список источников** (особенно YMYL), дисклеймер для медицины/финансов.
11. **Блок автора** (фото, ФИО, должность, стаж, ссылка на карточку) + «проверено экспертом X».
12. **Даты**: дата обновления видна. По кейсу 0050 удаление даты создания (оставить только «обновлено») дало рост блога ~×2,5 — Google брал старую дату и считал статью устаревшей. В YMYL — даты публикации, обновления и проверки.
13. Внизу: похожие статьи, комментарии (вопрос-CTA в конце текста; фейковые «50 комментариев при 2 визитах» не писать).

**Типографика текста:** предложения ~10 слов (30 — слишком длинно); абзацы ≤6 строк / ~500 знаков; выделения ключевых мыслей; картинка примерно каждые 1,5 экрана с осмысленным alt («Замок Карла I, вид сверху») и именем файла транслитом; объём = средний по релевантному топу +20–30% (раскрытие, а не вода; «вода» = бесполезные факты).

**Ссылки из тела текста:** на релевантные категории/листинги (в «топ-10 X» — 10 ссылок на 10 листингов), ~2 коммерческих анкора на статью, на связанные статьи; внешние — на авторитетные источники без nofollow.

**Микроразметка:** минимум `Article`/`BlogPosting` + `BreadcrumbList`; по необходимости `Person` (автор), `FAQPage` (только если FAQ видим), `HowTo`, `AggregateRating` (только при реальном голосовании). Шаблоны — `schema-and-rendering.md`.

**Тайтл:**
- SEO-формула: ключ + модификатор + УТП + бренд — «Ремонт квартир в Москве недорого — под ключ от 2 500 ₽ | СтройЭксперт».
- GEO-формула (тестировать): экспертность → ключ → доверие → уникальность — «Лицензированная компания по ремонту квартир с опытом 15 лет в Москве».
- Цифры, квадратные скобки, год (актуализировать!), топоним для гео-запросов. Не обещать того, чего нет на странице.

## 4. Генерация с ИИ (пайплайн)

Длинный текст одним промптом = галлюцинации, смысловые повторы, однотипные блоки. Работает только поэтапно:

1. Собрать 5–6 конкурентов из топа: объём, подтемы, оформление, Title/Description.
2. Сгенерировать структуру → согласовать (человек).
3. Отдельный промпт на вступление (указать, от чьего лица: «специалист компании N»).
4. Отдельный промпт на каждый раздел H2 (куски ~50–300 слов; мелкие куски дают меньше ИИ-маркеров и точнее интент). Передавать: заголовок раздела, ключи и сущности раздела, факты из базы знаний/первоисточников, стиль редакции, целевую аудиторию и её «боли» (Jobs To Be Done).
5. Сборка → удалить повторы между кусками → проверить вхождения → редактор + фактчекинг (эксперт для YMYL).
6. Медиа, CTA, перелинковка, метатеги, разметка → публикация → отправка на индексацию.

**Системный промпт раздела (основа):**
```
Ты — [роль эксперта] с опытом [N лет], пишешь для [ЦА] на сайте [компания].
Раздел: «[H2]». Задача читателя: [JTBD/боль].
Обязательно: первое предложение — прямой ответ на вопрос раздела; конкретные цифры, сроки, цены
из данных ниже; используй сущности: [список]; ключи: [2–3 фразы, естественно].
Формат: абзацы ≤ 4 предложений, при перечислении — список, при сравнении — таблица.
Запрещено: выдумывать факты и цифры, которых нет в данных; вводные «в современном мире»,
«важно отметить»; длинные тире (используй «-» или «—» по стилю редакции), двойные пробелы,
невидимые Unicode-символы; канцелярит.
Данные: [факты, характеристики, первоисточники]
```

**«Очеловечивание» (0026):** максимальная лексико-грамматическая вариативность; без вводных слов и длинных соединительных оборотов; разговорные выражения, если позволяет ниша; без Unicode-мусора, двойных пробелов и длинных тире. Опора на сущности, а не на ключи.

**Правила:**
- Если за 2 промпта нет ≥80% нужного результата — новый чат, правки по одной ошибке за раз.
- Короткие тексты (≤600 знаков, 2 абзаца — описания карточек) можно автоматизировать полностью: «на двух абзацах негде наврать». Длинные — только с редактором.
- Калибровка массового производства: десятки статей → эксперт размечает ошибки → правки в промпт → через несколько итераций ошибок нет. Тяжелее всего первые 100–200 материалов.
- 100% генеративный сайт без редактуры рискует обвалом трафика за день; детекторы ИИ ненадёжны (один текст: 15% и 100% в разных сервисах) — не ориентироваться на них.
- Модели: черновик лонгрида — Claude; идеи — ChatGPT; фактчекинг/поиск — Perplexity.

## 5. Быстрая проверка текста до публикации

- [ ] Главное слово темы — в верхушке частотного словаря текста.
- [ ] Главред ≥ 7,5; Тургенев ≤ 3–5 (вода/стилистика, риск «Баден-Бадена»).
- [ ] Покрытие однословников из ТЗ ~60%+ (бренды/модели — обязательно).
- [ ] Ctrl+F по ключу: нет кусков, плотно забитых ключом.
- [ ] Первое предложение статьи и каждого H2 — прямой ответ.
- [ ] Есть таблица/список, цифры, FAQ, вывод, CTA.
- [ ] Факты проверены, источники указаны; нет «фантомных» цифр.
- [ ] Автор/эксперт, даты, разметка, alt, ссылки на категории.
- [ ] Тест полезности: попросить LLM «сделай краткую сводку» — короткая/пустая сводка = мало ценной информации.
- [ ] Уникальность ≥ 90% (для карточек товаров достаточно 50–60%: полезность важнее уникальности).

## 6. После публикации

- **Индексация**: отправить URL (Вебмастер, IndexNow; для Google — Indexing API / сервисы индексации, см. `tech-audit.md`).
- **Встала на 7–11 место** → переписать Title/Description, усилить первый абзац, добавить недостающие подтемы.
- **Через 1–6 месяцев**: новые запросы из Вебмастера/GSC → вписать или сделать новый блок (пример: добавили таблицу под запрос «таблица…» — статья выросла).
- **Refresh, а не новая статья**: обновить «Топ-2025» до «Топ-2026» (заголовок, модели, дата) — сохраняется история ПФ. Конверсионные статьи обновлять раз в 3–4 месяца, законы — по факту изменений, событийные — за месяц до даты, вечнозелёные — раз в год+. Просто сменить дату без правок бесполезно.
- **Обновление для GEO**: переписать введение, вывод в начало статьи и разделов, 2–3 новых абзаца, хвосты из fan-out и GSC — на первый экран.
- **Каннибализация инфо/коммерции**: убрать из статьи цены/коммерческие блоки, перехватывающие «цена X»; усилить вхождения на листинге; перекластеризовать.
- **Эффект блога** доказывать ассоциированными конверсиями (многоканальные последовательности), а не прямыми продажами.
- Конвертящие статьи — в меню и футер.

## 7. Внешние площадки (VC, Habr, Pikabu, Дзен, Клерк, DTF)

- Индексация за минуты, траст, YMYL-авторитет; чаще попадают в источники нейроответов (Дзен и Википедия — топ источников Алисы, VC/Pikabu — в топ-20).
- Рейтинг «мы №1» на своём сайте неубедителен для людей, на нейтральной площадке выглядит редакционным.
- Бесплатный аккаунт: ссылки/UTM → статус «коммерческий» → статья выпадает из ленты и индекса. Реклама — нативно в середине статьи, 1–2 ссылки максимум, продукт как решение задачи, низкий порог входа.
- «Популярное»: сильнейший сигнал — комментарии; первые 1–2 часа — 5–15 дочитываний + реакции. Заголовок: цифры, результат, противоречие расхожему мнению, личный кейс.
- Не копировать текст статьи сайта — писать отдельный материал (одна тема на нескольких площадках = несколько строк выдачи).

## Анти-паттерны

Нейрослоп без редактуры; копирование структуры одного конкурента; спам ключами; одна статья под самый частотный запрос вместо кластера; инфо и коммерция на одной странице; вымышленный автор «Доктор»; «пустая» подводка; старый год в заголовке; огромная картинка на первом экране; «опубликовать и забыть»; картинки из поиска без лицензии (иски 30–100 тыс. ₽).
